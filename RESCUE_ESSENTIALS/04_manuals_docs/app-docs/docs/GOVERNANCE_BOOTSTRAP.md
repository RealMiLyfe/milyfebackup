# MiLyfe Governance Bootstrap Plan

**Purpose:** Transition from developer-controlled prototype to community-governed Practice Town.

---

## Principles

1. **No founder keys on live pots.** Bootstrap keepers have sunset dates.
2. **Provisional roles die in 30 days** unless renewed by the community.
3. **The Oath cannot be amended** (bodily autonomy, childhood, exit, fail-closed).
4. **People own it** by running it, holding keys, voting, and forking if captured.

---

## Bootstrap Sequence

### Step 1: Lab (Now)
- [ ] Developer team operates all infrastructure
- [ ] No real money, no real governance
- [ ] All accounts are test accounts
- [ ] No claim of "citizenship" or authority

### Step 2: First Keepers (Practice Town launch)
- [ ] Identify 5-7 provisional keepers from Jacksonville community
- [ ] Each has explicit sunset date (90 days max)
- [ ] Keepers can: verify resources, approve personhood, moderate reports
- [ ] Keepers cannot: spend pot alone, change compact, access private data
- [ ] Every keeper action is logged and auditable
- [ ] First 30 days: weekly check-in with community

### Step 3: First Compact Ratification
- [ ] Draft compact published (from MiLyfe_COMPLETE.md §XII)
- [ ] 14-day discussion period (Talk stage)
- [ ] Practice simulation of governance
- [ ] Private ballot to ratify
- [ ] Requires simple majority of personhood-verified members
- [ ] Minimum 100 members before ratification is binding

### Step 4: First Real Governance
- [ ] Community proposes renewal or replacement of provisional keepers
- [ ] First proposal goes through full pipeline (Idea → Talk → Try → Decide)
- [ ] Sunset on bootstrap: all provisional authority expires
- [ ] New keepers elected through standard Voice process
- [ ] Developer team transitions to "contributor" role (no special keys)

### Step 5: Live Readiness
- [ ] Legal counsel confirms $MLY compliance for FL
- [ ] Security audit passed
- [ ] 100+ active members in Practice Town
- [ ] Community votes to promote to Live
- [ ] 5-of-7 human pause capability confirmed
- [ ] Emergency roles tested and documented

---

## Who Can Be a Keeper

- Personhood verified
- 90+ days as member
- No open moderation cases
- Accepts public audit of keeper actions
- Discloses conflicts of interest
- Rotates after 6 months (renewable once by vote)
- Cannot be a shop owner in the same place (conflict)

---

## What Keepers See vs. Don't See

### Can See
- Place health dashboard (aggregate numbers)
- Pending personhood introductions
- Expiring roles needing renewal
- Pot approval requests
- Safety escalations (strict need-to-know)
- Resource freshness status

### Cannot See
- Private messages
- Pocket balances
- Health information
- Exact locations
- Child data
- Legal papers
- Helper conversation content

---

## Fork Rights

Per the Oath: people own it by running it. If the community believes governance is captured:

1. Any member can fork the codebase (OSI-licensed)
2. Data export always works (take your profile)
3. Two forks can still message if both opt in (federation)
4. $MLY and standing start fresh in a fork
5. The Oath travels with the fork (it cannot be removed)
